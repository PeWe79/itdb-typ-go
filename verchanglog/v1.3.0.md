## 📋 版本概述

v1.3.0 的核心是企业微信认证的第二种对接方式：**统一认证中心（SSO）模式**——企业微信认证配置新增「认证方式」切换（直连企业微信 / 统一认证中心），选择统一认证中心后显示认证中心地址、应用标识与应用密钥配置项；本系统跳转统一认证中心（wecom-auth-center）完成企微扫码，认证中心携带一次性 ticket 回跳本系统完成登录或绑定，绑定关系、会话签发与审计记录与直连模式完全一致，多个内部系统可共用同一套企微应用配置。

另包含一项扫码登录交互修复与 Docker 镜像流水线增强。共 4 次提交，前后端与文档同步更新，Swagger 产物已重新生成。

---

## ✨ 新增特性

- **企业微信认证方式切换**：认证配置新增「认证方式」卡片切换（直连企业微信 / 统一认证中心），按方式渲染不同配置项与「配置步骤」指引；直连模式默认选中，旧配置无感兼容，两套凭据分别保存、切换互不丢失
- **统一认证中心（SSO）模式配置**：填写认证中心地址、应用标识（认证中心 `config.yaml` 中 `apps` 下的条目名）与应用密钥（与认证中心 `app_secret` 一致，AES 加密存储不回显），启用校验按模式分别要求对应凭据完整
- **SSO 扫码登录链路**：登录页选择企业微信后跳转认证中心完成扫码，认证中心携带一次性 ticket 回跳本系统 `/login`，后端以 `HMAC-SHA256` 签名调用认证中心 `/api/verify` 换取企业微信成员身份并按绑定关系签发会话；认证中心错误码（应用未注册、签名不匹配、时间偏差、凭证无效等）转译为中文提示
- **SSO 绑定链路**：右上角「绑定企微/解绑企微」入口在 SSO 模式下同样可用，弹窗扫码后 ticket 绑定当前登录用户，重复绑定返回 409；绑定、解绑、登录、注销的审计详情文案与直连模式完全一致
- **认证方式卡片悬浮反馈**：悬浮时缓慢上移、边框高亮，未选中卡片附加浅蓝背景色，禁用态不触发

## 🔄 API 变更

- 新增公开接口：`POST /api/auth/wecom/sso/callback`（统一认证中心扫码登录回调，ticket 换取令牌与用户信息）
- 新增需认证接口：`POST /api/auth/wecom/sso/bind`（统一认证中心扫码绑定，与当前登录用户建立绑定）
- 行为扩展：`GET /api/auth/wecom/authorize` 与 `GET /api/auth/wecom/bind-url` 在统一认证模式下返回认证中心登录地址（直连模式行为不变）；`GET/PUT /api/settings/auth/wecom` 配置项新增 `authMode`、`ssoBaseUrl`、`ssoAppID` 与 `hasSsoAppSecret`
- 权限模型无新增权限点：SSO 配置复用认证配置读写权限，绑定复用既有登录态

---

## 📊 数据库变更

- `settings_auth_providers` 表 `wecom` 行的 `config` JSON 新增 `authMode`（缺省归一为 `direct`）、`ssoBaseUrl`、`ssoAppID`、`ssoAppSecret`（加密存储）字段，服务启动与既有数据自动兼容，无表结构变更、无需手工迁移

## 🔄 升级说明

**从 v1.2.1 升级**（无需数据库迁移脚本）：

- Docker：拉取 `v1.3.0` 镜像或保持 `latest` 标签重新拉起容器即可
- Release 二进制：从 [GitHub Releases](https://github.com/zyx3721/itdb-new/releases) 下载对应平台包替换

**升级后说明**：

1. 已启用直连模式的实例行为与 v1.2.1 完全一致，无需任何调整
2. 如需启用统一认证中心模式：先部署 wecom-auth-center 并在其 `config.yaml` 的 `apps` 下为本系统新增条目（`domain` 填本系统外部访问地址、`callback_path` 填 `/login`、`app_secret` 填 32 位以上随机密钥）并重启；再到「系统配置 → 认证配置 → 企业微信」将认证方式切换为「统一认证中心」，填写认证中心地址、应用标识与应用密钥后保存启用，详见《完整手册》7.8 节
3. 其余行为与 v1.2.1 一致
