## 📋 版本概述

v1.0.0 是 itdb-new 的首个正式版本，基于 [zyx3721/itdb](https://github.com/zyx3721/itdb/) 全面重写：保留原有资产业务模型与旧库兼容导入能力，改用 Go + React 前后端分离架构重新实现，并重做权限、审计、备份与标签打印。

本仓库的提交历史自「项目初始化」提交起算，本节记录该版本对外交付的完整能力。后端使用纯 Go 的 SQLite 驱动，不需要 CGO、GCC 或外部数据库；前端为 React 19 控制台，构建后由 Nitro 提供 SSR；发布形态为单镜像 Docker 与多平台二进制两种。

## ✨ 新增特性

### 资产全生命周期管理

- 八类资源统一台账：硬件、软件、单据、代理、文件、合同、地点、机架，并可相互关联
- 硬件资产：序列号（含备用序列号）、网络信息（IPv4/IPv6/MAC）、CPU 与核心数、内存与硬盘、RAID 配置、维保与采购成本、所属部门与责任人
- 软件许可：标题加版本去重，按 CPU 与核心数校验授权口径，超限直接拒绝
- 合同：类型与子类型、续签记录、事件历史、备件清单，标题去重
- 地点：楼层平面图上传与区域热区标注；机架：U 位可视化、正反面视图、位置冲突校验
- 代理：硬件厂商、软件厂商、供应商、采购方、承包方五类，名称忽略大小写去重

### 资料字典

- 六类字典：硬件类型、合同类型（含子类型）、状态类型（自定义颜色）、文件类型、所属部门、标记
- 支持 Excel 模板下载、批量导入与导出
- 内置数据受编号与名称双重保护，重名或删除内置项由业务规则拦截

### 用户与权限

- 本地密码与 AD/LDAP 双模式登录，JWT 会话有效期 48 小时
- 内置 admin / operator / viewer 三角色，支持自定义角色与用户组批量授权
- 43 项细粒度权限，Key 形如 `模块.资源.操作`，勾选任一 `manage` 自动补全对应 `read`
- 找回密码邮件流程：图形验证码校验身份、邮箱验证码重置口令，并受发送冷却与限流窗口约束
- 前端隐藏无权入口，后端按权限逐接口校验，无权限返回 403

### 审计日志

- 登录注销、资产增删改、字典维护、系统配置、备份导入、标签打印等操作全量留痕
- 按模块、操作、目标、结果与详情记录，支持搜索、筛选与导出
- 无实际修改的保存不写日志，业务规则拒绝不产生失败噪音

### 备份与迁移

- 手动备份：可勾选按数据库实际引用的文件一并打包为 zip
- 定时备份：五段 Cron 计划执行，按保留天数自动清理过期文件
- 数据库导入：支持 `.db` 与 `.zip`，兼容旧项目数据库自动转换（仅迁移资产管理、资料管理与用户数据）
- 导入前自动备份当前数据库，缺失引用文件写入备份审计

### 标签打印

- QR 码标签设计器，内置多种标签纸预设
- 按选中硬件批量生成预览并打印或导出

### 统计与导航

- 仪表盘资产概览与状态分布
- 内置统计报表，返回数据与图表配置
- 按类型、部门、用户、代理等维度逐层定位资产的导航树

### 系统配置

- 品牌标识、找回密码安全时效、定时备份参数
- 用户、用户组、角色与权限管理
- AD/LDAP 认证配置与邮件通知配置，提供连通性测试与测试邮件发送

### 接口与部署

- 集成 Swagger/OpenAPI 文档，Swagger UI 位于 `/swagger/index.html`
- 单镜像 Docker 部署：Go 后端、Nginx 与前端 Nitro SSR 由 Supervisor 管理，对外只暴露 80 端口，一条 `docker run` 拉起
- 数据目录整体挂载，数据库、附件、备份与日志均落在宿主机
- CI 在推送版本标签后自动发布：Linux/macOS/Windows × amd64/arm64 六平台二进制、前端 SSR 产物包与 `SHA256SUMS` 校验和

## 🚀 性能优化

- 后端采用 `modernc.org/sqlite` 纯 Go 驱动，二进制以 `CGO_ENABLED=0 -ldflags="-s -w"` 编译，无 CGO 与 GCC 依赖，体积更小
- 字典、引用选项与权限数据由 `GET /api/bootstrap` 一次性下发，减少前端启动阶段的请求次数
- 构建资源由 Nginx 直接托管并启用一年期不可变缓存，避免静态资源经过 SSR 服务

## 🔧 重构优化

- 后端按职责分层：`cmd/server` 服务入口、`config` 配置加载、`router` 路由装配与按域拆分（assets/auth/common/settings/system）、`internal` 领域模型与仓储、业务编排与安全能力、`pkg/database` 基础设施
- 前端按业务域组织：`routes` 路由页面、`features` 业务域组件、`components` 复用组件、`lib` 会话认证与通用工具
- 重复的 JSON 请求体解析统一收敛至 `router/common` 的 `DecodeJSON`，保持请求体大小限制、未知字段校验与错误处理入口一致
- 控制台由服务端模板渲染重写为 React 19 + TanStack Start / Router / Query 单页应用

## 🔄 API 变更

v1.0.0 为首个版本，无历史接口对照。当前接口按模块分组如下：

- **认证**：`/api/auth/*`（登录、登出、当前用户、改密、找回密码流程）、`/api/public/base`
- **资产**：`/api/items`、`/api/software`、`/api/invoices`、`/api/agents`、`/api/files`、`/api/contracts`、`/api/locations`、`/api/racks` 及其详情、关联与下载子资源
- **字典与标记**：`/api/dictionaries`、`/api/tags/*`
- **标签打印**：`/api/labels/items`、`/api/labels/presets`、`/api/labels/preview`
- **统计与浏览**：`/api/reports`、`/api/browse/tree`、`/api/dashboard/summary`、`/api/bootstrap`
- **审计与维护**：`/api/history`、`/api/history/events`、`/api/backups/database`、`/api/import/database`
- **系统设置**：`/api/settings/{base,users,user-groups,roles,auth-provider,email}`

免认证接口仅限 `POST /api/auth/login`、`GET /api/auth/providers`、找回密码流程四个接口、`GET /api/public/base`、`GET /health`、`GET /api/health`；其余接口均需携带 `Authorization: Bearer <token>`。

## 📊 数据库变更

全新初始化，共 49 张表（36 张随初始化创建、13 张由系统配置模块按需创建）：

- **核心业务**：`items`、`software`、`contracts`、`invoices`、`files`、`agents`、`users`、`locations`、`racks`、`locareas`、`labelpapers`、`tags`、`actions`、`contractevents`
- **关联关系**：`item2inv`、`item2soft`、`item2file`、`itemlink`、`contract2item`、`contract2soft`、`contract2inv`、`contract2file`、`invoice2file`、`soft2inv`、`software2file`、`tag2item`、`tag2software`
- **资料字典**：`itemtypes`、`contracttypes`、`contractsubtypes`、`dpttypes`、`statustypes`、`filetypes`
- **系统与配置**：`settings`、`system_secrets`、`history`、`settings_base`、`settings_email`、`settings_auth_providers`、`settings_roles`、`settings_role_status`、`settings_user_profiles`、`settings_user_groups`、`settings_user_group_members`、`settings_user_group_roles`、`settings_user_roles`
- **找回密码**：`password_reset_captchas`、`password_reset_requests`、`password_reset_send_log`

数据库为 SQLite 单文件，默认路径 `data/itdb.db`；JWT 签名密钥持久化于 `system_secrets`，LDAP 绑定密码加密后存储。

## 🔄 升级说明

**全新部署**（无需数据库迁移脚本）：

- Docker：`docker run -d --name itdb --restart unless-stopped -p 80:80 -e ITDB_JWT_SECRET=<随机长字符串> -v "$(pwd)/data:/app/data" registry.cn-shenzhen.aliyuncs.com/zyx3721/itdb-new:latest`
- Release 二进制：从 [GitHub Releases](https://github.com/zyx3721/itdb-new/releases) 下载对应平台包与前端 SSR 包，解压后启动后端并运行 `node .output/server/index.mjs`

**从旧版 PHP itdb 迁移**：在「系统配置 → 数据备份 → 数据库导入」上传旧库 `.db` 或含附件的 `.zip`，系统识别旧结构并自动转换，仅迁移资产管理、资料管理与用户数据；系统配置、审计历史与标签预设保持当前默认，导入前会自动备份当前数据库。

**部署后必做**：

1. 使用 `admin / admin123` 首次登录后立即修改默认密码
2. 显式设置 `ITDB_JWT_SECRET`，多实例部署时必须设置
3. 生产环境通过 Nginx 启用 HTTPS，并按需收紧 `ITDB_CORS_ORIGINS`
